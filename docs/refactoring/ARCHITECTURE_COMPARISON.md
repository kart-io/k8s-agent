## 🏗️ Bootstrap 模式详解

### 组件依赖图（以 agent-manager 为例）

```
启动顺序（从上到下）：

┌─────────────────────────────────────┐
│  1. Logger (优先级 100)              │  ← 在 Initialize 中初始化
└─────────────────────────────────────┘
                │
┌───────────────▼─────────────────────┐
│  2. Database (优先级 300)            │  ← registerComponents
│     - 连接数据库                      │     bootstrap.Register()
│     - 初始化 Schema                   │
└─────────────────────────────────────┘
                │
┌───────────────▼─────────────────────┐
│  3. Redis (优先级 400)               │
│     - 连接 Redis                      │
│     - 测试连接                        │
└─────────────────────────────────────┘
                │
┌───────────────▼─────────────────────┐
│  4. Registry (优先级 450)            │
│     依赖: Database, Redis             │
└─────────────────────────────────────┘
                │
┌───────────────▼─────────────────────┐
│  5. NATS (优先级 500)                │
│     依赖: Registry, Database, Redis   │
└─────────────────────────────────────┘
                │
┌───────────────▼─────────────────────┐
│  6. Dispatcher (优先级 550)          │
│     依赖: NATS, Registry              │
└─────────────────────────────────────┘
                │
┌───────────────▼─────────────────────┐
│  7. HTTP Server (优先级 600)         │
│     依赖: Registry, Dispatcher        │
└─────────────────────────────────────┘
                │
┌───────────────▼─────────────────────┐
│  8. gRPC Server (优先级 700)         │  ← 可选
│     依赖: Registry, Dispatcher        │
└─────────────────────────────────────┘
                │
┌───────────────▼─────────────────────┐
│  9. Health Check (优先级 900)        │  ← 最后启动
└─────────────────────────────────────┘
```

### 生命周期管理

```
┌──────────────┐
│   main()     │
└──────┬───────┘
       │
       │ app.Execute()
       ▼
┌──────────────────────────────────────────────┐
│  commonapp.RunWithRunner()                   │
│  ┌────────────────────────────────────────┐ │
│  │ 1. 解析命令行参数                       │ │
│  │ 2. 加载配置文件                         │ │
│  │ 3. 处理环境变量                         │ │
│  └────────────────────────────────────────┘ │
└──────┬───────────────────────────────────────┘
       │
       │ app.Initialize(ctx, opts)
       ▼
┌──────────────────────────────────────────────┐
│  {Service}App.Initialize()                   │
│  ┌────────────────────────────────────────┐ │
│  │ 1. 初始化日志                           │ │
│  │ 2. 转换配置                             │ │
│  │ 3. 创建 Bootstrap                       │ │
│  │ 4. 注册所有组件（不执行初始化）          │ │
│  └────────────────────────────────────────┘ │
└──────┬───────────────────────────────────────┘
       │
       │ app.Run(ctx)
       ▼
┌──────────────────────────────────────────────┐
│  {Service}App.Run()                          │
│  ┌────────────────────────────────────────┐ │
│  │ bootstrap.Run(ctx, nil)                │ │
│  │   ├─ 按优先级初始化所有组件             │ │
│  │   ├─ 等待信号 (SIGINT/SIGTERM)         │ │
│  │   └─ 触发优雅关闭                       │ │
│  └────────────────────────────────────────┘ │
└──────┬───────────────────────────────────────┘
       │
       │ 收到信号
       ▼
┌──────────────────────────────────────────────┐
│  {Service}App.Shutdown(ctx)                  │
│  ┌────────────────────────────────────────┐ │
│  │ bootstrap.Shutdown(ctx)                │ │
│  │   └─ 按相反顺序关闭所有组件             │ │
│  └────────────────────────────────────────┘ │
└──────────────────────────────────────────────┘
```

```
Bootstrap 模式:
┌─────────────────────────────────────────┐
│ main.go                    ~15 lines    │
│ app/app.go                ~180 lines    │
│ app/options/options.go    ~200 lines    │
│ internal/initializers/*   ~100 lines/个 │
│                                         │
│ 总计: ~500-800 lines                    │
└─────────────────────────────────────────┘

Simple 模式:
┌─────────────────────────────────────────┐
│ main.go                    ~15 lines    │
│ app/app.go                 ~60 lines    │
│ app/server.go             ~150 lines    │
│ config/options.go         ~150 lines    │
│                                         │
│ 总计: ~375 lines                        │
└─────────────────────────────────────────┘
```

### 功能对比表

| 特性 | Bootstrap | Simple | 说明 |
|-----|-----------|--------|------|
| 组件依赖管理 | ✅ 自动 | ❌ 手动 | Bootstrap 自动处理依赖顺序 |
| 优雅关闭 | ✅ 自动 | 🔶 半自动 | Bootstrap 反向关闭所有组件 |
| 启动顺序控制 | ✅ 精确 | ❌ 无 | 通过优先级精确控制 |
| 组件重用 | ✅ 高 | 🔶 中 | 初始化器可跨服务重用 |
| 学习曲线 | 🔶 陡峭 | ✅ 平缓 | Simple 更容易理解 |
| 代码量 | 🔶 多 | ✅ 少 | Simple 代码量少 30-40% |
| 适合场景 | 复杂服务 | 简单服务 | |
| 测试友好度 | ✅ 高 | 🔶 中 | Bootstrap 组件独立测试 |
| 扩展性 | ✅ 强 | 🔶 中 | Bootstrap 易于添加新组件 |

## 📈 服务复杂度评分

### 评分标准

```
复杂度计算公式:
Score = (外部依赖数 × 3) + (服务器数 × 2) + (是否有消息队列 × 3) + (是否有定时任务 × 2)

分级标准:
- Score >= 10: 使用 Bootstrap 模式
- Score < 10:  使用 Simple 模式
```

### 各服务评分

| 服务 | 外部依赖 | 服务器 | 消息队列 | 定时任务 | 得分 | 推荐模式 |
|-----|---------|--------|---------|---------|------|---------|
| agent-manager | 3 (DB,Redis,NATS) | 3 (HTTP,gRPC,Health) | ✅ | ❌ | 9+6+3+0=18 | Bootstrap ✅ |
| orchestrator | 3 (DB,Redis,NATS) | 1 (Health) | ✅ | ✅ | 9+2+3+2=16 | Bootstrap ✅ |
| cluster | 1 (DB) | 2 (HTTP,Health) | ❌ | ❌ | 3+4+0+0=7 | Simple... 🤔 |
| reasoning | 1 (DB) | 2 (HTTP,Health) | ❌ | ❌ | 3+4+0+0=7 | Simple... 🤔 |
| auth | 2 (DB,Redis) | 2 (HTTP,Health) | ❌ | ❌ | 6+4+0+0=10 | Bootstrap 🤔 |
| collect-agent | 0 | 1 (Health) | ✅ | ✅ | 0+2+3+2=7 | Simple ✅ |
| gateway | 0 | 2 (HTTP,Health) | ❌ | ❌ | 0+4+0+0=4 | Simple ✅ |
| monitor | 0 | 2 (HTTP,Health) | ❌ | ❌ | 0+4+0+0=4 | Simple ✅ |

**注意**: cluster 和 reasoning 虽然得分不高，但考虑到：
- cluster: 有 25+ 个 K8s API 端点，业务复杂度高
- reasoning: 有 LLM、向量存储等复杂子系统

建议使用 Bootstrap 模式以便未来扩展。
