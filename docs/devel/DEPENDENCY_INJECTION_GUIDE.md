# 依赖注入指南

## 概述

本项目使用 [Google Wire](https://github.com/google/wire/wire) 进行编译时依赖注入，以减少样板代码、提高代码可维护性并在编译时检测依赖问题。

## 为什么使用 Wire？

### 优势

1. **编译时检查**：Wire 在编译时生成代码，可以在编译阶段发现依赖问题
2. **零运行时开销**：生成的是纯 Go 代码，没有反射，性能最优
3. **类型安全**：完全类型安全，IDE 支持友好
4. **易于调试**：生成的代码可读，便于理解和调试
5. **减少样板代码**：自动处理依赖传递，减少手动参数传递

### 对比手动依赖注入

**优化前（手动）：**
```go
func (a *AuthApp) registerComponents(bs *bootstrap.Bootstrap) error {
    // 1. Database
    a.dbInit = initializers.NewDatabaseInitializer(a.opts, a.logger)
    bs.Register(a.dbInit)

    // 2. Redis
    a.redisInit = initializers.NewRedisInitializer(a.opts, a.logger)
    bs.Register(a.redisInit)

    // 3. Session Service (需要传递 dbInit 和 redisInit)
    a.sessionInit = initializers.NewSessionServiceInitializer(
        a.opts,
        a.logger,
        a.dbInit,    // 手动传递
        a.redisInit, // 手动传递
    )
    bs.Register(a.sessionInit)

    // ... 9个组件，大量重复代码
}
```

**优化后（Wire）：**
```go
func (a *AuthApp) registerComponents(bs *bootstrap.Bootstrap) error {
    // Wire 自动处理所有依赖注入
    components, err := InitializeAuthComponents(a.opts)
    if err != nil {
        return fmt.Errorf("failed to initialize components: %w", err)
    }

    // 批量注册
    bs.Register(components.DB)
    bs.Register(components.Redis)
    bs.Register(components.Session)
    // ... 等等

    return nil
}
```

## 项目结构

每个服务的 Wire 配置位于 `cmd/<service>/app/` 目录下：

```
cmd/<service>/app/
├── app.go           # 主应用逻辑
├── components.go    # 组件定义（不受构建标签限制）
├── wire.go          # Wire 配置文件（wireinject 构建标签）
└── wire_gen.go      # Wire 生成的代码（!wireinject 构建标签）
```

## 文件说明

### 1. components.go

定义组件容器和提供者函数，无构建标签限制：

```go
package app

import (
    "github.com/kart-io/k8s-agent/cmd/cluster/app/options"
    "github.com/kart-io/k8s-agent/internal/cluster/initializers"
    pkginitializers "github.com/kart-io/k8s-agent/pkg/initializers"
    "github.com/kart-io/logger/core"
)

// ClusterComponents 包含所有组件初始化器
type ClusterComponents struct {
    DB     *initializers.DatabaseInitializer
    HTTP   *initializers.HTTPServerInitializer
    Health *pkginitializers.HealthCheckInitializer
}

// NewClusterComponents 创建组件容器
func NewClusterComponents(
    db *initializers.DatabaseInitializer,
    http *initializers.HTTPServerInitializer,
    health *pkginitializers.HealthCheckInitializer,
) *ClusterComponents {
    return &ClusterComponents{
        DB:     db,
        HTTP:   http,
        Health: health,
    }
}

// ProvideLogger 提供 logger 实例
func ProvideLogger(opts *options.ServerOptions) (core.Logger, error) {
    return opts.InitLogger()
}
```

### 2. wire.go

Wire 配置文件，定义依赖关系：

```go
//go:build wireinject
// +build wireinject

package app

import (
    "github.com/google/wire"
    "github.com/kart-io/k8s-agent/cmd/cluster/app/options"
    "github.com/kart-io/k8s-agent/internal/cluster/initializers"
    pkginitializers "github.com/kart-io/k8s-agent/pkg/initializers"
)

// InitializerSet Wire 依赖集合
var InitializerSet = wire.NewSet(
    ProvideLogger,
    initializers.NewDatabaseInitializer,
    initializers.NewHTTPServerInitializer,
)

// HealthInitializerSet 健康检查依赖集合
var HealthInitializerSet = wire.NewSet(
    pkginitializers.NewHealthCheckInitializer,
    wire.FieldsOf(new(*options.ServerOptions), "Health"),
)

// InitializeClusterComponents 自动注入所有组件
func InitializeClusterComponents(opts *options.ServerOptions) (*ClusterComponents, error) {
    wire.Build(
        InitializerSet,
        HealthInitializerSet,
        NewClusterComponents,
    )
    return nil, nil
}
```

### 3. wire_gen.go

Wire 生成的代码（已提交到代码库）：

```go
// Code generated by Wire. DO NOT EDIT.

//go:generate go run github.com/google/wire/cmd/wire
//go:build !wireinject
// +build !wireinject

package app

import (
    "github.com/kart-io/k8s-agent/cmd/cluster/app/options"
    "github.com/kart-io/k8s-agent/internal/cluster/initializers"
    pkginitializers "github.com/kart-io/k8s-agent/pkg/initializers"
)

// InitializeClusterComponents 自动生成的注入代码
func InitializeClusterComponents(opts *options.ServerOptions) (*ClusterComponents, error) {
    logger, err := ProvideLogger(opts)
    if err != nil {
        return nil, err
    }
    databaseInitializer := initializers.NewDatabaseInitializer(opts, logger)
    httpServerInitializer := initializers.NewHTTPServerInitializer(opts, logger, databaseInitializer)
    healthOptions := opts.Health
    healthCheckInitializer := pkginitializers.NewHealthCheckInitializer(healthOptions, logger)
    clusterComponents := NewClusterComponents(databaseInitializer, httpServerInitializer, healthCheckInitializer)
    return clusterComponents, nil
}
```

## 构建标签说明

Wire 使用构建标签来区分配置文件和生成文件：

- `//go:build wireinject`：仅在运行 `wire` 命令时使用
- `//go:build !wireinject`：正常编译时使用（排除 wire.go）

这样确保：
- 运行 `go build` 时使用生成的 `wire_gen.go`
- 运行 `wire` 时使用配置文件 `wire.go`

## 使用 Wire

### 生成代码

```bash
# 生成所有服务的 Wire 代码
make gen.wire

# 或者手动生成单个服务
cd cmd/<service>/app
wire
```

### 编译服务

```bash
# 直接编译（使用已生成的 wire_gen.go）
make build.<service>

# 或
go build -o bin/<service> cmd/<service>/main.go
```

**注意**：`wire_gen.go` 已提交到代码库，因此无需安装 `wire` 工具即可编译。

### 修改依赖

1. 修改 `wire.go` 中的 Provider Set
2. 运行 `wire` 重新生成代码
3. 提交 `wire_gen.go` 的变更

## Wire 高级特性

### 1. Provider Sets

将相关的 Provider 组织在一起：

```go
// 基础依赖
var BaseProviderSet = wire.NewSet(
    ProvideLogger,
    initializers.NewDatabaseInitializer,
    initializers.NewRedisInitializer,
)

// 业务依赖（复用基础依赖）
var BusinessProviderSet = wire.NewSet(
    BaseProviderSet,
    initializers.NewWorkflowInitializer,
    initializers.NewStrategyInitializer,
)
```

### 2. 字段选择

从结构体中提取字段：

```go
var HealthInitializerSet = wire.NewSet(
    pkginitializers.NewHealthCheckInitializer,
    wire.FieldsOf(new(*options.ServerOptions), "Health"),
)
```

### 3. 接口绑定

将具体类型绑定到接口：

```go
var InitializerSet = wire.NewSet(
    NewConcreteService,
    wire.Bind(new(ServiceInterface), new(*ConcreteService)),
)
```

## 最佳实践

### 1. 文件组织

- `components.go`：放置所有无构建标签限制的代码
- `wire.go`：仅包含 Wire 配置
- `wire_gen.go`：由 Wire 生成，不要手动编辑

### 2. 命名约定

- Provider 函数：`Provide<Type>`（如 `ProvideLogger`）
- Initializer 函数：`New<Type>Initializer`
- Component 容器：`<Service>Components`

### 3. 依赖管理

- 保持依赖树简单清晰
- 避免循环依赖（Wire 会在编译时检测）
- 使用 Provider Sets 组织相关依赖

### 4. 错误处理

Provider 函数可以返回错误：

```go
func ProvideLogger(opts *options.ServerOptions) (core.Logger, error) {
    return opts.InitLogger()
}
```

Wire 会自动传播错误。

## 故障排查

### 问题：wire 命令未找到

```bash
# 安装 Wire
go install github.com/google/wire/cmd/wire@latest
```

### 问题：循环依赖

Wire 会报告循环依赖错误。解决方案：
1. 重新设计依赖关系
2. 引入接口打破循环
3. 将部分逻辑移到 Initialize 方法中

### 问题：类型不匹配

确保：
1. Provider 函数签名正确
2. 参数类型与构造函数参数类型一致
3. 使用 `wire.Bind` 进行接口绑定

## 迁移指南

### 从手动依赖注入迁移到 Wire

1. **创建 components.go**：定义组件容器
2. **创建 wire.go**：定义 Wire 配置
3. **运行 wire**：生成 `wire_gen.go`
4. **更新 app.go**：使用 `Initialize<Service>Components`
5. **验证编译**：`go build`
6. **提交所有文件**：包括 `wire_gen.go`
